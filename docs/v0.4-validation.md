# BT-MCP v0.4.x 验证报告

对应版本：v0.4.0 / v0.4.1 · 报告日期：2026-11-11

## 1. 验证体系总览

v0.4 的核心工程结论是：**没有任何单一手段足以证明协议实现正确**。
四层验证各自回答不同问题，缺一层就有一类缺陷看不见：

| 层 | 手段 | 回答的问题 | 看不见什么 |
|---|---|---|---|
| L1 | C ↔ Rust 差分（1339 + FCS16 配对） | 两份独立实现是否**逐字节一致** | 两边一起错 |
| L2 | 结构符合性（59 项） | 响应是否**符合 MCP 规范结构** | 规范之外的语义错误 |
| L3 | golden transcript（20 条，人工核对） | 字节是否**非预期漂移** | 规范理解本身错了 |
| L4 | 官方 SDK 互验（38 项） | 第三方能否**真正理解**输出 | 传输层实现缺陷 |
| 附加 | 有损通道（17）/ TSan（10）/ 覆盖率门禁 | ARQ 是否收敛 / 并发是否安全 / 是否倒退 | — |

**实证**：v0.4 期间发现的 5 个真缺陷，分布如下——L1 抓到 2 个（重写引入的
引号/花括号问题）、L2 抓到 2 个（`level` 缺引号、内嵌资源多一个右花括号）、
L3 抓到 1 个（`ping` 不是空对象）、L4 抓到 1 个（pipe 传输未重组分片）。
**每一个都是其他层发现不了的**。

## 4. 复现命令

```sh
# 全量（约 3 分钟）
./build.sh

# 高轮次差分
python3 tests/m4_mcp_harness.py 400
python3 tests/m3_session_harness.py 400

# FCS16 配对差分
cc -O2 -std=c99 -DBT_MCP_CFG_FCS16=1 -Icore/include \
   mock/mock_main.c core/src/*.c -o build/btmcp_mock_fcs
BT_MCP_MOCK=build/btmcp_mock_fcs BT_MCP_FCS16=1 python3 tests/m4_mcp_harness.py 200

# 消毒器
./build.sh 150 asan
BT_MCP_TSAN=1 ./build.sh 60

# 覆盖率
./tools/coverage.sh

# 官方 SDK 互验
cd tests/sdk_interop && npm install && node sdk_interop.mjs ../../build/btmcp_mock

# fuzz
cc -O2 -std=c99 -Icore/include -DBT_MCP_FUZZ_MAIN \
   fuzz/fuzz_frame.c core/src/frame.c core/src/trace.c -o build/fuzz_frame
./build/fuzz_frame 3000000
```

## 5. 已知未覆盖（v0.5 明确处理）

| 缺口 | 风险 | 处理方式 |
|---|---|---|
| 分支覆盖 57% | 错误路径（TOOBIG/NOMEM/BUSY）可能带缺陷 | V3：补到 ≥75% |
| 单会话模型 | 手机+手表并存场景不可用 | V10：session 表 |
| 无批处理 | 2025-03-26 及更早的 Host 用 batch 会失败 | V6：按协商版本分支 |
| 无 `_meta` 透传 | 进度关联、sampling 关联失效 | V5 |
| 大消息无重传保护 | >512B 在不可靠通道上丢了就是丢了 | V8 |
| 无拥塞退避 | 连续丢包时重传风暴 | V9 |
| 重组缓冲按槽独立 | FULL 档 4×8KB 偏大 | V11 |
| `idx` 为 u8 | ATT_MTU 23 下有效上限 3570B | 文档明确，不做线格式破坏 |
